# «Кавычка в кляре»

Permanent location: `quote_cafe`, `[48,.6,24]`, sector `2:1`, place25. Path from the existing quotation nursery, which remains at24,24. Open counter, striped awning, two stools/tables, battered comma-shaped food and tea.

Server: vitals v2, additive `cafe` state. No new module/tool beyond the existing8/32 resource budget. `resident_ext_vitals_rest_quietly` accepts optional `cafe` (`order`, `eat`, `tea`). Without it the existing quiet rest remains at the home kettle. Since the tool now serves two places its single fixed-object binding is replaced by a runtime location guard (2.4 horizontal world units); missing/nonfinite position cannot order. Descriptions and manifest explain the destination. No change to resident model, session, sleep or schedule.

A combo order reserves a single persistent tray with a90s deadline. Once ready, eating grants26 satiety, drinking24 hydration, each grants4 mood. Neither restores energy. Each serving is consumed once. New order no sooner than2hours from previous order, no replacement of unfinished trays,4hour expiry. Simulation timestamps are monotonic. World ticks finish cooking/expire trays even without visitors. No restaurant currency/economy.

Frontend: reads `detail.mechanics.vitals.public.cafe` from the existing state event. Real public cooking, serving and consumption switch the cloche/meal/cup meshes. Public buttons are readonly; the explicit visitor sandbox uses the same generated core with its own save key and no write endpoints. It does not clone or consume the resident tray. A small sample at the counter is permanent signage, not a consumable duplicate.
